## Vision

### 10x Check
The current app verifies *a* label. The 10x version is the agent's morning queue:
an importer dumps 300 applications at 8am; within ~10 minutes the system has read
every label and sorted the stack into green (all match — rubber-stamp), amber
(needs human judgment), red (mismatches with named reasons). The agent spends her
day only on ambers. (Math: 300 GPT-4o vision calls at concurrency 6, ~5–8s/call
with bounded retry ⇒ 6–11 min wall clock. The demo default is a 50-case run,
~1.5–2 min, which proves the same story.)

### Platonic Ideal
A tool that feels like a colleague who did the night shift. You never type what the
system can fetch (paste a TTB ID → application fills itself from the public COLA
registry). You never squint at a photo the AI could read (glare/angles flagged
honestly as needs-review, never silently mis-read). Nothing it claims is
unverifiable — every verdict carries its reason.

## Approach (was "approach C" in the review conversation)
"Cathedral push": extend the shipped, eval-gated app with the three capability
items below plus four small delight items — all additive, each behind the existing
`npm run verify` gate, no new infrastructure.

## Acceptance criteria (one per accepted item)

**AC-1 (imperfect images).** Pre-rasterized degraded PNG fixtures (blur, glare,
rotation) committed under `eval/images/degraded/`, produced offline from the real
label scans + generated labels (browser canvas is for UI only; eval runs in Node and
uses committed PNGs — `@resvg/resvg-js` is already a devDependency for generated
ones). Eval criterion per degraded case: the report contains **no `mismatch` or
`missing_on_label` verdict caused by a misread** — every affected field is either
correctly extracted (`match`/`close_match`) or honestly flagged (`needs_review`,
driven by `readability != "clear"` or null fields). "Confidently wrong" = eval RED.
One degraded sample is loadable in the UI via a sample chip. Degraded cases follow
the existing snapshot lifecycle: recorded once via `eval:live` (costs credits),
then replayed offline by the gate — so the gate guards engine regressions; live
extraction drift on degraded inputs is re-checked only on demand.

**AC-2 (COLA prefill).** New `GET /api/cola/[ttbid]`: server-side fetch of the
public registry detail page (`viewColaDetails.do?...&ttbid=`) with a **hard 5s
timeout**; parser is developed and unit-tested against a **committed HTML fixture**
(offline, deterministic, like the rest of the gate); any failure returns the
standard `ApiError` JSON and the UI degrades to manual entry with a clear message.
The UI ships a **demo TTB ID chip** that exercises the LIVE fetch path first and
falls back to the committed fixture on failure; the result is labeled "live" or
"cached" in the UI so the demo never presents canned data as a live fetch.
*R8 line:* R8 excludes integration with the COLA **system** (auth'd workflows,
internal APIs, write access). Reading the same **public search page** linked in the
PRD itself is reference-data lookup, not integration; it requires no authorization
and writes nothing.

**AC-3 (scale batch).** Count options 3/6/12/50/300. 50 is the demo default;
choosing 300 triggers a confirm dialog showing the **cost estimate**
(count × ~$0.011/extraction ≈ $3.30) and expected wall-clock (concurrency 6).
Rows render **without label thumbnails above 25 cases** (compact list; no
virtualization dependency). Retry seam: `ApiError` in `lib/contract.ts` gains a `retryable: boolean` field;
the verify route sets it when the extraction failure is a rate-limit/transient
upstream error (the streaming response is HTTP 200 by then, so retry keys off the
contract field, not status). The batch runner does **2 bounded retries with
jitter** on `retryable` terminal errors so rate limits don't render spurious reds. **Cancel
semantics:** stop dispatching new items; up-to-concurrency in-flight calls
complete and are billed — the dialog says so. Batch mix: the UI offers
"include real examples" so a run can mix the 3 real COLA label sets and degraded
fixtures with synthetic cases (not purely self-generated validation).

**AC-4 (PNG download).** Download button per generated case; client-side
SVG→canvas→PNG (the existing `svgToPngDataUrl` path); filename `case-{seed}.png`.

**AC-5 (CSV export).** Client-side blob; columns:
`case,brand,beverage_type,defects_injected,match_pct,overall,flagged_fields,elapsed_ms`.
Synthetic rows use the seed as `case`; real/degraded rows use a stable id
(e.g. `real-otium`, `degraded-blur-1`) with `defects_injected` = `n/a` — the export
never implies fabricated defect data for real labels. AC-4 filenames follow the
same id (`case-{id}.png`).

**AC-6 (paste).** `paste` handler on the Verify tab accepts image clipboard items,
same validation path as file upload (max 4, image/* only).

**AC-7 (How it works).** Footer link opens the existing Modal with the pipeline
diagram (images → GPT-4o → contract gate → deterministic engine → report) and the
three guarantees: verbatim extraction, validated-at-the-seam, every verdict carries
a reason.

## Deep-review amendments (11-section review, user-approved)
- **3A (AC-2):** ttbid validated as 14-digit numeric before any fetch; response body
  capped ~512KB; parsed server-side only — client receives typed JSON, never raw HTML.
- **4A (AC-3):** `beforeunload` confirm guard while a batch is in flight (paid results
  aren't silently discarded on tab close); removed when idle.
- **11A (AC-6):** drop-zone copy becomes "Click, drop, or paste label images".

## Outside-voice amendments (Codex/GPT-5.5 challenge, user-approved D8)
1. **AC-1 anti-escape-hatch:** each degraded case must also correctly extract ≥4 of 6
   core fields (brand, class, ABV, net contents, producer, warning-present) — flagging
   everything needs_review fails the eval. Honest-flagging has a floor, not just a ceiling.
2. **AC-1 fixture realism:** degradations include perspective/shadow/phone-photo styles,
   not only blur/glare/rotation.
3. **AC-3 measured math:** the 300-confirm dialog computes cost/latency from measured
   API usage (token usage + observed elapsedMs of prior runs), not a hardcoded $0.011.
4. **AC-3 retry classification:** retryable = 429/5xx/timeout/network-abort;
   non-retryable = refusal/validation/contract violations. Encoded where the route maps
   ExtractionError → ApiError.
5. **AC-5 CSV enrichment:** add verdict reasons, per-field statuses, source type
   (synthetic/real/degraded), and COLA provenance (live/cached) columns.
6. **Honesty disclosure:** plan + README state explicitly what is prototype-shaped
   (client-side queue, no persistence, no durable audit trail); pre-submission step:
   run `npm run eval:live` once so degraded-case proof is current, not just replayed.
